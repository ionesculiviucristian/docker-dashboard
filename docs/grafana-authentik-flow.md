# Grafana ↔ Authentik integration (detailed flow)

Companion to [grafana-oauth-config.md](grafana-oauth-config.md) which documents the env vars. This doc explains how the pieces fit together at runtime.

## The two sides of the link

### Authentik (IdP / OAuth2 server)

Configured by `services/authentik/deploy.py::_configure_grafana_oidc`. Creates two Authentik entities:

**OAuth2 Provider `grafana-provider`** — the technical config of the OAuth client:
| Field | Value | Source |
|---|---|---|
| `client_id` | `grafana` | `.env` (`GRAFANA_GF_AUTH_GENERIC_OAUTH_CLIENT_ID`) |
| `client_secret` | random, generated by Authentik on create | persisted back to `.env.custom` after creation |
| `signing_key` | "authentik Self-signed Certificate" | bootstrap default; signs JWT/ID tokens |
| `authorization_flow` | `default-provider-authorization-implicit-consent` | bootstrap default; skips per-app consent prompt |
| `invalidation_flow` | `default-provider-invalidation-flow` | bootstrap default; runs on logout |
| `property_mappings` | 3 managed scopes: `openid`, `email`, `profile` | bootstrap defaults |
| `redirect_uris` | `https://grafana.gr8.ro/login/generic_oauth` (strict) | hardcoded in deploy.py |
| `access_token_validity` | `hours=24` | hardcoded |
| `refresh_token_validity` | `days=30` | hardcoded |

**Application `grafana`** — the user-visible link that wraps the provider:
- Slug `grafana` → URLs become `/application/o/grafana/...`
- Bound to `grafana-provider` via `provider=provider.pk`
- `meta_launch_url` = `https://grafana.gr8.ro` → shown as a tile in Authentik's app library
- `policy_engine_mode=any` → any matching policy grants access (no AND-restrictions)

### Grafana (OAuth client / Relying Party)

Configured via `GF_AUTH_GENERIC_OAUTH_*` env vars in `services/grafana/docker-compose.yml`. Full table in [grafana-oauth-config.md](grafana-oauth-config.md). The key wiring is the 4 URLs that point at Authentik:

| Var | URL | Used by |
|---|---|---|
| `AUTH_URL` | `https://authentik.gr8.ro/application/o/authorize/` | Browser (HTTPS public) |
| `TOKEN_URL` | `http://authentik-server:9000/application/o/token/` | Grafana server (Docker internal HTTP) |
| `API_URL` | `http://authentik-server:9000/application/o/userinfo/` | Grafana server (Docker internal HTTP) |
| `SIGNOUT_REDIRECT_URL` | `https://authentik.gr8.ro/application/o/grafana/end-session/` | Browser (HTTPS public) |

## Bootstrap sequence

Order matters — Grafana needs `CLIENT_SECRET` from Authentik. The orchestrator is `dashboard.py` calling `pre_deploy()` then containers up then `post_deploy()` per service.

```
1. authentik/deploy.py::pre_deploy()
   - envs.generate(AUTHENTIK_BOOTSTRAP_TOKEN)
   - envs.generate(AUTHENTIK_SECRET_KEY)
   - create_network(authentik)
   - register_service_hostname(authentik.gr8.ro)

2. grafana/deploy.py::pre_deploy()
   - envs.generate(GRAFANA_GF_SECURITY_ADMIN_PASSWORD)   ← random break-glass
   - create_network(grafana)
   - register_service_hostname(grafana.gr8.ro)
   - register_service_hostname(grafana-alloy.gr8.ro)

3. start_containers([all compose files])
   - Authentik server + worker boot, run migrations, create default bootstrap user
   - Grafana boots WITH oauth enabled but CLIENT_SECRET empty (env interpolation
     of unset var → empty string, not "?err" because that var has no :?err)
   - Auto-login attempts fail at this point — bootstrap window.

4. authentik/deploy.py::post_deploy()
   a. wait_for_container(postgres) until pg_isready
   b. create_postgres_db(authentik DB + user)
   c. AuthentikAPI(base_url=https://authentik.gr8.ro/api/v3, token=BOOTSTRAP_TOKEN).wait_ready()
   d. _configure_traefik_forward_auth(api):
      - AuthentikProxyProvider("traefik-forward-auth-provider").ensure(...)
      - AuthentikApplication("traefik-forward-auth").ensure(...)
      - AuthentikOutpost(EMBEDDED).attach_provider(provider.pk)
   e. If GRAFANA_GF_AUTH_GENERIC_OAUTH_CLIENT_SECRET already set → skip OIDC config (idempotent re-deploy)
   f. _configure_grafana_oidc(api):
      - lookup 3 managed scopes (openid, email, profile)
      - lookup authorization + invalidation flows
      - lookup signing key
      - AuthentikOAuth2Provider("grafana-provider").ensure(...) ← creates if missing
      - returns provider.client_secret
      - AuthentikApplication("grafana").ensure(...)
   g. envs.set("GRAFANA_GF_AUTH_GENERIC_OAUTH_CLIENT_SECRET", secret, custom=True)
      → persisted to .env.custom (gitignored)
   h. start_containers([grafana compose], recreate=True)
      → Grafana restarts, this time with CLIENT_SECRET present
      → OAuth flow now functional
```

Idempotency: every step uses `get(...) or create(...)`. Re-running deploy after a successful run is a no-op (returns early at step 4e).

## Login flow (Authorization Code + PKCE)

User opens `https://grafana.gr8.ro/`. Browser steps `<==>` Grafana, Grafana server-side steps `~~>` Authentik internal.

```
[1] Browser → Grafana                  GET https://grafana.gr8.ro/
[2] Grafana → Browser                  302 → AUTH_URL?...
        Location: https://authentik.gr8.ro/application/o/authorize/
          ?client_id=grafana
          &response_type=code
          &scope=openid+profile+email
          &redirect_uri=https://grafana.gr8.ro/login/generic_oauth
          &state=<random_csrf>
          &code_challenge=<sha256(code_verifier)>
          &code_challenge_method=S256

[3] Browser → Authentik (via Traefik)  GET /authorize?...
        (HTTPS, public)

[4] Authentik checks session:
    - Not logged in?  → runs flow "default-authentication-flow":
                         show identification page → password → MFA if configured
    - Already logged in? → skips to authorization
    - "implicit consent" flow → does NOT prompt user to approve scopes for "grafana"

[5] Authentik → Browser                302 → redirect_uri?code=...&state=...
        Location: https://grafana.gr8.ro/login/generic_oauth
          ?code=<one_time_auth_code>
          &state=<same_random_csrf>

[6] Browser → Grafana (via Traefik)    GET /login/generic_oauth?code=...&state=...

[7] Grafana verifies state matches the one it issued in step [2].

[8] Grafana ~~> Authentik              POST TOKEN_URL    (Docker internal HTTP)
        POST http://authentik-server:9000/application/o/token/
        Content-Type: application/x-www-form-urlencoded
          grant_type=authorization_code
          code=<one_time_auth_code>
          client_id=grafana
          client_secret=<CLIENT_SECRET>
          redirect_uri=https://grafana.gr8.ro/login/generic_oauth
          code_verifier=<original PKCE secret>           ← proves Grafana is the same RP that started [2]

[9] Authentik <~~ Grafana              200 OK
        {
          "access_token": "...",
          "refresh_token": "...",
          "id_token": "<JWT>",
          "token_type": "Bearer",
          "expires_in": 86400
        }

[10] Grafana decodes id_token (JWT):
     - verifies signature against Authentik's signing key (cached, refreshed via JWKS endpoint)
     - extracts claims: sub, email, preferred_username, name, iat, exp, aud

[11] Grafana ~~> Authentik             GET API_URL with Bearer access_token
        GET http://authentik-server:9000/application/o/userinfo/
        Authorization: Bearer <access_token>

[12] Authentik <~~ Grafana             200 OK
        {
          "sub": "...",
          "email": "...",
          "email_verified": true,
          "preferred_username": "...",
          "name": "...",
          "given_name": "...",
          "family_name": "..."
        }

[13] Grafana applies JMESPath mappings (from env):
     - login_attribute_path "preferred_username" → username
     - email_attribute_name "email"               → email
     - name_attribute_path "name"                 → display name

[14] Grafana checks its DB for that login:
     - exists?  → reuse user, update profile fields, KEEP existing org_role
     - not exists? AND ALLOW_SIGN_UP=true → create with org_role from GF_USERS_AUTO_ASSIGN_ORG_ROLE=Admin

[15] Grafana issues session cookie    Set-Cookie: grafana_session=<sealed>

[16] Grafana → Browser                 302 → /

[17] Browser → Grafana                 GET / with grafana_session cookie

[18] Grafana → Browser                 200 OK + UI
```

State / PKCE protection: step [2] generates a `state` (CSRF token) and `code_verifier` (PKCE secret) stored server-side in the Grafana login session. Step [7] verifies `state` echoed back, step [8] sends the `code_verifier`. Authentik validates that `SHA256(code_verifier) == code_challenge` sent in step [2]. This makes the auth code unusable by an attacker who intercepts it.

## Logout flow (RP-Initiated Logout)

```
[1] Browser → Grafana                 GET /logout
[2] Grafana invalidates grafana_session, deletes refresh_token from its DB
[3] Grafana → Browser                  302 → SIGNOUT_REDIRECT_URL
        Location: https://authentik.gr8.ro/application/o/grafana/end-session/
[4] Browser → Authentik                GET /application/o/grafana/end-session/
[5] Authentik runs the invalidation_flow:
    - deletes the Authentik session token for this user-agent
    - revokes refresh tokens linked to this client_id
[6] Authentik → Browser                302 → its home / login page
```

Without `SIGNOUT_REDIRECT_URL`, step [3] would be skipped — the Authentik session would survive, and the next time the user hits Grafana, `AUTO_LOGIN=true` would silently re-authenticate via the still-valid Authentik session (no password prompt). This is the difference between "logged out of Grafana" and "logged out everywhere".

## Network topology

| Call | From | To | Protocol | Path |
|---|---|---|---|---|
| `/authorize` | Browser | Authentik | HTTPS via Traefik | `https://authentik.gr8.ro/application/o/authorize/` |
| `/login/generic_oauth` callback | Browser | Grafana | HTTPS via Traefik | `https://grafana.gr8.ro/login/generic_oauth` |
| `/token` | Grafana container | Authentik container | HTTP, Docker net `authentik` | `http://authentik-server:9000/application/o/token/` |
| `/userinfo` | Grafana container | Authentik container | HTTP, Docker net `authentik` | `http://authentik-server:9000/application/o/userinfo/` |
| `/end-session` | Browser | Authentik | HTTPS via Traefik | `https://authentik.gr8.ro/application/o/grafana/end-session/` |

Mixed HTTP/HTTPS rationale:
- **Browser ↔ server** = HTTPS, public DNS, through Traefik. The browser doesn't know about the internal Docker network.
- **Server ↔ server** = HTTP, internal Docker network `authentik` (which `grafana` joins via `networks:` in its compose). Skipping Traefik means: no TLS handshake, no cert-trust issues, no dependency on Traefik being up, faster, traffic never leaves the host.

This requires `grafana` to be on Authentik's network. Check `services/grafana/docker-compose.yml::networks` — `authentik` is listed.

## Failure modes

| What breaks | Observable behavior |
|---|---|
| Authentik server container down | Browser redirect to `/authorize` fails. Grafana login impossible. Existing Grafana sessions survive until cookie expiry. |
| `TOKEN_URL` / `API_URL` unreachable | Step [8] fails. Grafana log: `oauth: failed to obtain token` or `oauth: error retrieving userinfo`. User sees "OAuth callback error" page. |
| Wrong `CLIENT_SECRET` | Step [9] returns 401. Grafana log: `oauth: client authentication failed`. |
| `redirect_uri` mismatch | Step [4] returns 400 from Authentik: `redirect_uri_mismatch`. Edit the provider's `redirect_uris` in Authentik or fix `GF_SERVER_ROOT_URL`. |
| Authentik signing key rotated | Old `id_token` JWTs fail signature verification. Grafana fetches new JWKS automatically. Existing sessions unaffected (Grafana uses its own session cookie, not the JWT). |
| Authentik DB volume lost | Provider, Application, Outpost gone. Re-run deploy — idempotent, will recreate. `CLIENT_SECRET` in `.env.custom` is now stale; need to delete it so deploy regenerates. |
| Grafana DB volume lost | All Grafana users gone. Next login → first user gets created with `Admin` role via `AUTO_ASSIGN_ORG_ROLE`. No data persistence issue beyond Grafana's own state. |
| `.env.custom` deleted (has `CLIENT_SECRET`) | Grafana env interpolation gets empty string. `/token` calls fail. Deploy detects empty secret → re-runs `_configure_grafana_oidc` → finds existing provider via `get()` → returns its `client_secret` — wait, `get()` does NOT return the secret, only `create()` does. **Re-deploy with provider already created and lost CLIENT_SECRET = stuck.** Have to delete the provider in Authentik admin UI first, then re-deploy. |

The last row is a known sharp edge — `client_secret` is only returned by Authentik at provider creation time. The deploy script's idempotency assumes the secret is preserved in `.env.custom`. Losing one without the other breaks re-deploy.
